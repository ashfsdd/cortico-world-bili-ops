# B站运营薄入口

给 Coo 加一个 `bili_ops` 工具，把命令原样转发给本机的 **bili CLI**。不在插件里写业务逻辑，命令手册放本地记忆，用到才查。

## 为什么

B 站运营有几十个命令（投稿、查数据、改封面、发动态），全塞进提示词会占掉几万 token。这个插件只做一件事：**转发**。

## 装之前要有

- **bili CLI 已经装好并能跑**（在命令行敲 `bili` 有输出）
- Coo 0.2.23 或以上

## 首次配置清单

这个插件只有一个配置项：`envPrompt`。

| 配置 | 填什么 | 不填会怎样 |
| :-- | :-- | :-- |
| `envPrompt` | 一段**写给 AI 看的说明**：bili CLI 在哪、常用命令有哪些、什么场景该用 | 插件照常工作，但 AI 不知道有哪些命令可用，会瞎猜 |

**最小示例**：

```
bili CLI 在 PATH 里，直接敲 bili 就能用。
常用：bili video list（列投稿）、bili video info <bvid>（看数据）、bili dynamic post "内容"（发动态）。
不确定的参数先跑 bili --help。
```

### 配完自检

让她调一次 `bili_ops`，参数 `["--help"]`，看能不能返回 bili 的帮助文本。

## 怎么用

```
bili_ops({ args: ["--room", "123456789", "live", "info"] })
```

`args` 是字符串数组，**长文本也放数组元素里**，避免被空格拆开。

## 风险

- 这个工具**会执行本机命令**（通过 bili CLI）。转发前不做二次校验。
- 只应该在**信任的会话**里开放。
- bili CLI 的登录态（Cookie）不经过这个插件，由 CLI 自己管。
